- CI had been red since 2025-12-01 (the `prek` job). Root cause was not in this repo:
  mdformat-mkdocs renumbers an ordered list starting at N != 1 down to `1.`, which turns
  <ol start="5"> into <ol>, and mdformat's HTML-equivalence check then refuses to write the
  file. MULTILINGUAL_ANALYSIS.md numbered its implementation plan 1-10 continuously across
  three Phase headings, so the `5.` and `8.` lists each tripped it. Worked around by
  restarting each phase list at 1, deliberately NOT by adding the file to the hook's
  exclude. The real fix is filed in mdformat-mkdocs/doing.txt.

  mdformat_slw.mdit_plugins, which does not exist here (slw registers no markdown-it syntax
  and RENDERERS is empty). Now points at mdformat.text(source, extensions={"slw"}), the
  only path that actually reaches slw's regexes. The file is in _skip_if_exists so the edit
  survives future updates.

- scripts/canary_repos.json landed empty, so tox -e canary is a no-op.

- Resolved: all three canary bugs from the 2026-07-27 run. 18d083e swaps the U+00A0 wrap
  guard for an internal control character (UNWRAPPABLE_SPACE) that is restored to a space
  after wrapping, so author-written nbsp still survives and link text comes back out with
  plain spaces. db1c229 applies the same guard to inline code spans. 18e393e, generalized
  in bcb5d85, pulls any token that would open a block construct (setext underline,
  blockquote, ATX heading, thematic break, bullet, ordered marker) back onto the previous
  line, since inside a rendered paragraph such a line start is always a wrapping artifact.

  scripts/canary_repos.json. Five repos, all green.

- Deliberately not tracked, both blocked outside slw:
  python-poetry/poetry uses Hugo shortcodes. Core mdformat alone already rewrites
  `[install]({{< relref ... >}})` to `\[install\]` (12 new escapes in basic-usage.md with
  no plugins loaded), so its docs are not mdformat-formattable without a Hugo plugin. The
  residual slw-specific part is that wrapping can leave a line ending in a bare `<`, which
  the next pass escapes. Same family as bcb5d85 but on the trailing edge; worth fixing if
  a Hugo-flavored consumer ever shows up.
  pydantic/pydantic uses `!!! note` admonitions. Without mdformat-mkdocs installed the
  admonition is parsed as a plain paragraph, and _collapse_whitespace flattens the
  four-space continuation indent, which changes the parse on pass 2. Core mdformat alone is
  idempotent on that file. The fix is to run slw alongside mdformat-mkdocs, not to change
  slw.
