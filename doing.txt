Core mdformat alone already rewrites `[install]({{< relref ... >}})` to `\[install\]` (12 new escapes in basic-usage.md with no plugins loaded), so its docs are not mdformat-formattable without a Hugo plugin. The residual slw-specific part is that wrapping can leave a line ending in a bare `<`, which the next pass escapes. Same family as bcb5d85 but on the trailing edge; worth fixing if a Hugo-flavored consumer ever shows up. pydantic/pydantic uses `!!! note` admonitions. Without mdformat-mkdocs installed the admonition is parsed as a plain paragraph, and _collapse_whitespace flattens the four-space continuation indent, which changes the parse on pass 2. Core mdformat alone is idempotent on that file. The fix is to run slw alongside mdformat-mkdocs, not to change slw.
